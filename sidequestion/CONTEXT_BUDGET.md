ARTEX는 독립 출력 예산, 최근 내용과 누적 요약, 제한된 복구 방식을 참고했습니다. 당시 norma v0.3.6의 구조화 메시지와 도구 쌍을 유지하고 Grok의 텍스트 발췌를 그대로 복사하지 않았으며, OpenCode의 메인 세션 압축 이벤트를 ARTEX 메인 transcript에 기록하지 않았습니다.

## 요청 예산과 실행

- norma의 내용 블록별 UTF-8 바이트 추정과 4/3 여유분을 사용하며 시스템 프롬프트, 도구 schema 및 메시지 래핑 비용을 추가합니다. 모델의 정확한 토큰 수는 아닙니다.
- 보조 출력의 기본 상한은 8192 tokens이며 메인 설정의 출력 상한도 넘지 않습니다. 서비스 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS`로 256–32768 범위의 상한을 설정할 수 있습니다. 제품 기본 모델이나 메인 작업 매개변수는 바꾸지 않습니다.
- 입력 예산은 컨텍스트 창에서 출력 상한과 안전 여유를 뺀 값입니다. 창 크기가 알려지지 않으면 플랫폼 기본 200K를 사용합니다. 안전 여유는 창의 5%이며 최소 128, 최대 8192 tokens입니다.
- 성공한 문답은 증가하는 순번으로 한 번에 최대 20쌍을 읽습니다. 원문은 최대 20쌍을 유지하며 토큰 예산은 입력 예산의 최대 1/4, 최대 16K입니다.
- 초과한 문답은 누적 요약에 반영합니다. 요약에는 역사적 출처와 컨텍스트 시각을 붙입니다. 이전 어시스턴트 답변은 새로운 도구 증거가 아니므로 충돌하면 최신 메인 스냅샷을 우선합니다.
- 메인 컨텍스트가 여전히 길면 사본의 오래된 메시지만 요약하고 최근 내용은 최대 8K tokens를 보존합니다. 잘라내는 경계가 도구 호출과 결과를 나누지 않으며 너무 큰 단일 묶음은 통째로 요약합니다.
- 요약 입력은 실제 남은 창에 맞춰 UTF-8 안전 분할하며 출력 상한은 2048 tokens입니다. 빈 요약, 잘림, 도구 호출 또는 요약 예산 초과 결과는 캐시하지 않습니다. 보조 질문 한 번에 최대 12회 요약하며 같은 120초 제한을 적용합니다. 상한에 도달하면 명시적으로 실패하며 무한 반복하지 않습니다.
- 모델이 처음 컨텍스트 초과를 반환했고 아직 텍스트나 도구 호출을 출력하지 않았다면 더 줄인 뒤 최대 한 번 재시도합니다. 추정 크기가 줄지 않으면 즉시 복구를 중지합니다. 다른 모델 오류나 부분 스트리밍 출력은 이 복구를 유발하지 않습니다.
- 요약, 실패한 시도, 취소 시점의 사용량 등 확보한 모든 사용량을 같은 보조 요청에 누적합니다. Provider가 사용량을 반환하지 않으면 0만 기록할 수 있으며 추정을 실제 사용량으로 가장하면 안 됩니다.

## 영구 저장과 화면

`side_question_sessions.memory`는 이전 문답 요약, 반영한 ordinal 및 스냅샷 식별자로 캐시한 메인 컨텍스트 요약을 저장합니다. `side_question_requests.context_info`는 준비 단계, 실제 재생한 문답 수, 요약 사용 여부 및 예산 추정을 저장합니다.

요약은 원래 요청이 실행 중이고 정리 버전이 일치할 때만 저장합니다. 초기화 시 캐시도 지우고 늦게 도착한 쓰기가 정리된 데이터를 복원하지 못하게 합니다. 새 스냅샷은 이전 스냅샷 요약을 재사용하지 않습니다. 요약 필드는 v3 작업 보관에 포함하고, 기존 v3에 필드가 없으면 빈 객체로 채웁니다. v1/v2 호환성도 유지합니다.

POST는 먼저 요청을 접수·반환하고 준비·압축은 백그라운드에서 수행하며 승인 잠금이나 DB 트랜잭션을 유지하지 않습니다. SSE와 기록에는 준비, 문답 정리, 사본 압축, 답변 단계를 표시합니다. 압축 실패는 해당 보조 요청의 실패 최종 상태로 저장합니다. 프런트엔드는 오류를 유지하고 실패한 질문을 초안으로 복원하며 입력창을 가리는 떠 있는 오류 알림은 사용하지 않습니다. 기록 폴링이 제출 오류를 지우지 않도록 했습니다.
